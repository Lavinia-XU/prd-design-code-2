# 体验目标撰写规范

## 概览

本文件用于把需求分析中的核心用户、业务场景、关键痛点、Demo范围和页面能力，压缩为整体输出中的一小段体验目标内容。体验目标由3条目标选项和一段画面感组成，用于说明用户在核心任务中的能力跃迁与结果确定性。

## 输入来源

直接使用本 Skill 已完成的需求分析内容作为输入，包括：

- 需求概括：本需求要解决的问题和业务背景。
- 体验痛点：用户当前完成核心任务时的阻力、成本、依赖或不确定性。
- 主要用户角色：真实使用者的岗位、职责和任务。
- 核心场景与功能映射：本次Demo进入页面设计的3-5个重点场景。
- Demo范围判断：只取平台内可展示、可操作、可演示的内容。

如果缺少精确数据，基于需求中的现状描述给出保守、可替换的区间或定性对比，例如“从依赖人工逐项判断，转为在同一页面内完成定位与处置”。

## 撰写步骤

1. 锚定同一个核心 Job：识别用户在本次需求中最重要的一件事，避免把目标拆成多个互不关联的小功能点。
2. 提炼现状 A：从需求中找出用户当前的主要卡点，如耗时长、依赖专家、路径分散、判断依据不透明、处置结果不确定。
3. 定义目标 B：描述新方案让用户获得的能力跃迁，如更快定位、更少跨角色依赖、更清楚判断风险、更确定地完成闭环。
4. 选择1-3个体验维度：只选择强相关维度，可从快、准、省、稳、易理解、信任感、专业、掌控感中选取。
5. 生成3条体验目标：每条围绕同一个核心 Job，从不同侧重点表达；度量或A到B对比直接融入句子，不单独写“度量标准”。
6. 生成一段画面感：用前后反差描述用户过去如何卡住、新方案如何跨过门槛、最终获得什么确定性结果。

## 输出格式

```markdown
### 1.2 体验目标

#### 目标选项
- **目标选项 1（偏业务闭环/结果确定性）**：<一句话，说明角色在核心场景中获得的结果确定性，并内嵌A到B对比或度量>
- **目标选项 2（偏用户能力跃迁/独立性）**：<一句话，说明角色从依赖协作/经验转为可独立完成，并内嵌A到B对比或度量>
- **目标选项 3（偏防错确定性/效果感知）**：<一句话，说明角色能更清楚判断、校验或恢复，并内嵌A到B对比或度量>

#### 画面感
<一段话，突出过去卡点、新方案跨越、确定性结果和业务价值；控制在120-180字。>
```

## 表达要求

- 体验目标必须是整体输出的一小部分，控制篇幅，不展开长篇解释。
- 三条目标必须服务于同一个核心 Job，只是侧重点不同，不要写成三个零散功能点。
- 不写底层技术实现手段，不堆砌算法、接口、数据汇聚等技术原理。
- 将对比或度量直接融入句子，例如“从跨3个页面反复核对，压缩为在同一列表完成定位与处置”。
- 使用专业、简洁、可落地的语言，避免口号化、过度修饰和流水账。

## 禁止表达

禁止使用以下无法证伪或过于空泛的表达：

- 提升体验
- 优化视觉
- 变得更好
- 更加便捷
- 更加智能
- 更加友好

禁止把体验目标写成：

- 单个页面、按钮、字段或操作步骤的局部优化。
- 三个互不关联的小功能点。
- 只描述系统做了什么，不说明用户能力发生什么变化。
- 只描述操作变少，不说明业务判断、结果确定性或风险掌控如何变化。
